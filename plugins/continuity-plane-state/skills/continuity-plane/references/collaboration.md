# Codex planning and executor operations

The planning MCP is independent of advanced State claims. Use continuity_plan for Todo/card/inbox/reference metadata, and continuity_help to inspect the exact shared CLI parameter contract. If a request adds explicit work, extend the current card-backed Todo instead of maintaining another private queue. Keep completed evidence when priorities change.

Codex's native PostCompact route can inject a bounded current handoff. A second compact SessionStart must not duplicate it. Never promote an old active Work merely because the State service returns one. Prefer the native current instruction and verified session return point; a stale lease is a State synchronization issue, not a ban on ordinary project work.

Before a worker starts, use collaboration prompt to bind its identity, checkout, actual task body and applicable complete rules. rules export is the full-policy entry; the small recovery packet carries discovery information and attachment hashes. Maintain reusable official-document references outside Git, with reviewed versions and applicability rather than unsupported claims of having read them.

Execution is explicit CLI work: dispatch selects configured adapters, worker resume preserves a recorded provider thread, and report pages the captured final output. --model auto uses current suitable configured executors; --fallback-model grants a finite transient-failure alternative. Usage limits are recoverable quota exhaustion, not content-policy refusal; official-subscription profiles record supplied resets and keep the recorded thread after recovery. For queued capacity, use `worker dispatch --enqueue` with one single-instance `worker queue run`; host pause does not kill live workers. Neither authentication nor content-policy refusal permits automatic provider hopping. quota report shows recorded observations; native Claude quota auto-query is not provided. Supported native queries stay within their owning host/profile.

For a controller takeover, use handoff show for the versioned plan plus current observations; a missing session return point does not mean the project has no handoff. Bounded output retains pending decisions and blocked/failed/report-mismatch attention before ordinary changes. Report presence is not a passing verdict. handoff write --auto creates evidence-linked draft candidates without changing the declared plan. SessionEnd or a changed observed host boot can mark a native child lost to observation; silence alone cannot prove it exited.

For a new controller/model, controller start returns a bounded packet of declared plan, effective workflow profile, approved relevant memory and next action without a full scene scan. The profile covers communication/reporting style, question policy and tool habits, not authorization. Private memory and native-note candidates stay on the owning member/host; native ingestion needs exact path consent and never follows discovered links. Repository knowledge requires explicit export plus Git review. ACK means delivered, not understood or approved. Use handoff show for fresh workers, reports, inbox and drift.

The fast handoff write path persists declarations and defers observations. Inbox send may omit message_id and returns the generated final ID; explicit IDs stay idempotent. Acknowledge one ID, a bounded time window, or a bounded all operation before archive. MCP tool errors carry structured failed_gate/isError fields, not raw Python exceptions. Archived IDs suppress duplicate sends. Quota/rate/capacity cooldowns bind the observed origin/model; unknown quota resets never become fabricated retry times. Reservation conflicts state live/stale/unknown status, attempt/result evidence and next steps.

For durable listening, use collaboration changes --consumer NAME, process the returned page, then pass its next_cursor with --ack on the next read. Reads without acknowledgement replay; never acknowledge high_water_cursor or omitted rows. Reset only explicitly with --reset-consumer --since CURSOR. A truncated view is not a complete task list.

If dispatch reports an executor mismatch or changed task snapshot, do not start a separate command with the rejected prompt. Refresh the card and prepare again; --reassign --actor CALLER --assignee TARGET is an explicit transfer, subject to owner/creator and running-worker checks. A card-projected Todo labels assigned versus live running state and retains blocker reasons. For many shell-sensitive updates, use task update --batch with JSON or stdin. Upstream replay refusal requires a reviewed new-session plan, not another blind resume of the same thread.

At delivery, put passing required checks, optional unverified work and the exact commit in structured evidence. Record batches and source-bound decisions, then use status-render for a reproducible collaboration view. The generated view is not authoritative State and grants no merge, publication or deployment permission. A normal progress note does not end the user's agreed implementation stage.

Dependencies use stable task IDs and gate claim, active transition and dispatch. Local and Gitea task lists share one paged envelope. Reservation inventory distinguishes live, stale and unknown jobs; after reboot, use lease-guarded reconcile-host before assuming capacity is full. Capacity is scoped to project, host, profile and client family. MCP itself is host-owned and may require a new host connection.
