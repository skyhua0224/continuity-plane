# 使用场景

[English](use-cases.en.md) · [工作流](workflows.md) · [能力与验证](validation.md)

以下描述问题与当前可用入口，不是所有问题已完全解决的声明。历史实验数字只放在[原方法](benchmarks.md)，不推广到新版或真实项目。

## 压缩后像换了一个人

安装并实际启用 hook 后，用有界 session 返回点和共享主控交接保存下一步、约束、批次、在途任务与待决事项。没有 hook 的宿主仍要显式读取 handoff／packet；工具不能替代所有对话语义，也不保证自动阈值压缩成功。

## 同一仓库的多个 Session 会互相踩踏

显式主控租约、原子派发预留和 controller run 协调经过工具的操作。它不是 OS 隔离，也不保护绕过工具的 Git。跨机先选权威宿主并升级参与客户端，不直接共享正在写的 SQLite 文件。

## 多人和多 Agent 不知道别人已经做了什么

卡片、变更流、报告与批次提供共同记录；wait 可以阻塞等事件。消息由收件方取并 ack，不保证唤醒任意会话。MCP 重连后的执行者归属仍有易用性缺口，不能把连接 ID 当作永恒身份。

## 临时 Idea 很容易把主线带跑

轻量使用者可记录 commitment、lesson 和 next_action，保留未了结事项。完整类型化 Idea／Work 切换属于显式 State 高级路径；普通讨论不自动成为新任务或额外授权。

## 大型项目里，人和 AI 都不知道“哪里是哪里”

已知符号用有界 lookup，包含／链接依赖使用当前可索引关系，派卡附代码路标。它不是完整 compiler call graph 或任意多语言影响分析；图形投影和完整 UI 有独立覆盖说明。空命中后继续窄范围源码调查。

## Memory、Skill 和文档会漂移

规则以摘要／哈希附件交付，资料保留版本／章节／采用理由，经验和更正可共享。drift 检查路径、引用与卡片等已实现范围。来源 TSV 专用导入导出尚缺，不要求用户手工维护两套来源记录；记录和提醒都不等于实际采用。
