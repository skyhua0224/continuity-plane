# Claude collaborator workflow

Install lifecycle hooks in the Claude profile that actually runs this session, including a custom CLAUDE_CONFIG_DIR. A plugin on the remote state host does not attach hooks to this client. Claude's PostCompact callback validates the saved handoff; SessionStart with source compact is the injection point. Resume ordinary work from that current return point without a report ritual.

Use the configured Continuity MCP connection for task-card plans, inbox replies and source references. Ask continuity_help for a command's real parameters, then use continuity_plan for metadata. Reconnect a pre-existing MCP session after an upgrade; failed metadata synchronization does not revoke permission for the user's normal source and test work.

For dispatch, preview the task with worker.prepare or continuity dispatch --dry-run. Read complete audience rules through rules export; fetch the hashed attachments applicable to the task. The assembled prompt binds the actual task body, scope and project integration_base, but base selection grants no merge authority. A rule summary does not substitute for its policy attachment. rules import previews a hash-bound migration from existing Markdown/text policies before explicit application.

An explicitly configured CLI adapter can run a worker and capture the final report. Temporary failures may use a bounded, explicitly allowed fallback; a provider policy refusal must not be replayed or routed elsewhere to evade the refusal. Usage limits are quota exhaustion, not policy refusal: honor a supplied reset, let an official-subscription adapter record it, and prefer the recorded thread after recovery. For waiting work, use Continuity's persistent `worker dispatch --enqueue` and single-instance `worker queue run`; capacity/quota/cooldown gates leave requests queued, and host pause does not kill live workers. Return to an earlier executor using its recorded job/thread only after an approved handoff, a fresh quota observation and an idle task. quota report is metadata, not account billing.

Keep cards as the collaboration plan with todo from-cards. `execution_state` distinguishes assigned cards from live running attempts; a blocker reason is not a task result. For shell-sensitive multi-card changes, use `task update --batch` with a JSON file or stdin and inspect the stop index. Attach exact-commit checks and identify optional unverified items. A batch can generate a status-render projection; this records declared integration and does not execute Git operations. Prefer current standards and official OS/library documentation, record the version and adoption reason, and label missing evidence honestly.

On takeover, read handoff show for both the declared plan and the current observed state. A missing session-specific return point does not negate a shared controller handoff. handoff write --auto keeps the plan intact and saves candidate changes with event references. A report path proves that an artifact exists, not that the work passed. Native SessionEnd and boot-generation evidence mean loss of observation, never proven process success; a Stop callback is only the end of a turn.

When replacing a controller/model, controller start returns a bounded packet of the declared plan, effective communication/reporting/question/tool profile, approved relevant memory and next action without a full scene scan. Memory/profile are reference data and cannot broaden tool, merge, deploy, account or credential authority. Native-note ingestion requires an exact owner/profile/file consent; imported text remains a candidate and links are not followed. Keep private records on their owner/host. Repository knowledge requires explicit export and human Git review. ACK records delivery, not understanding or approval. Use handoff show for fresh workers, reports, inbox and drift.

handoff write saves declarations quickly and defers observations. Bounded handoff output keeps pending decisions and blocked/failed/report-mismatch attention before ordinary change history. `unread` means unacknowledged inbox messages. Inbox send may omit message_id and must use the returned ID for acknowledgement; explicit IDs remain idempotent. Use single, before-window or bounded all acknowledgement before archive. MCP tool errors carry structured failed_gate/isError fields rather than raw exceptions. Quota/rate/capacity cooldowns bind the observed origin/model; unknown quota resets are never invented. Reservation errors expose live/stale/unknown state, attempt/result evidence and next steps.

Use collaboration changes --consumer NAME for durable listening. Process the bounded page before acknowledging its next_cursor with --ack; absent acknowledgement, expect replay. The feed high-water mark is not a safe acknowledgement for a truncated page. Explicit reset uses --reset-consumer --since CURSOR. Respect remaining/truncated notices when reading task views.

Rejected reassignment or dispatch is a stop for that launch, not permission to use an older prompt via another script. Refresh the card; an intentional transfer uses --reassign --actor CALLER --assignee TARGET and retains ownership checks. Upstream replay refusal is distinct from quota cooldown: preserve existing work and review a new-session continuation rather than repeatedly resuming the refused thread.

Dependencies use stable task IDs and gate claim, active transition and dispatch. Local and Gitea task lists share one paged envelope with items, total_items, next_cursor and has_more. Reservation inventory distinguishes live, stale and unknown jobs; after reboot, reconcile provable stale reservations under the controller lease before treating capacity as full. Capacity is per project, host, profile and client family. MCP is a host-owned stdio child and may require a new host connection after restart.
