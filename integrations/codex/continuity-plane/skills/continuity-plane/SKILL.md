# Continuity Plane / 连续性控制面

- `[continuity.resume.current-state]` 在执行任何动作前读取注入的 resume packet。 / Read the injected resume packet before acting.
- `[continuity.resume.bounded-read]` resume 后只读取项目的 bounded `.continuity/STATUS.current.md` 路由；若与 packet 冲突，以 State packet 为准。 / After resume, read only the project's bounded `.continuity/STATUS.current.md` routing projection; State packet wins on conflict.
- 每个 MCP Session 首次使用写工具前，用绝对项目根调用一次 `continuity_resume` 建立绑定；绑定后不得切换项目根。 / Before the first MCP write in a session, call `continuity_resume` once with the absolute project root; never switch roots after binding.
- `[continuity.work.sticky]` 继续 packet 中的 active Work 和 claim，不自行发明另一个 active task。 / Continue its active Work and claim; do not invent a different active task.
- `[continuity.effect.read-only]` `read_only: true` 禁止写代码、提交、部署、新 Work 和普通 State 写。允许两条窄化恢复路径：lease 有效且仅 canonical source 变更时，同一 owner 调用 `continuity_claim_recover(heartbeat)`；lease 已过期时用新 claim identity 调用 `continuity_claim_recover(reclaim)`。两者均要求 verified checkpoint；source stale 时在同一 Event 重绑当前 source evidence、续租或换签 claim 并刷新 checkpoint。其他只读原因继续 fail closed。 / Treat `read_only: true` as a veto on code, commits, deployments, new Work, and ordinary State writes. Two narrow recovery paths are allowed: same-owner `continuity_claim_recover(heartbeat)` when the lease is valid and only canonical sources changed; and `continuity_claim_recover(reclaim)` with a new claim identity after lease expiry. Both require a verified checkpoint. When sources are stale, the same Event rebinds current source evidence, heartbeats or replaces the claim, and refreshes the checkpoint. All other read-only causes fail closed.
- 源 freshness、revision 或 lease 可能变化时，重新运行 `continuity resume --root <project>`。 / Re-run it when source freshness, revision, or lease may have changed.
- 在重要边界创建 checkpoint，并在压缩后或交接写入前验证。 / Create a checkpoint at a material boundary and verify it before post-compaction or handoff writes.
- 只能通过 checkpoint-bound completion tool 完成 Work，不直接编辑 State。 / Complete Work only through the checkpoint-bound completion tool; do not edit local State directly.
- 当前 Work 是已声明 return point 的依赖叶时，证据准备完毕后直接调用 `continuity_work_transition`；该工具在一个 State Event 中完成依赖、释放旧 claim、解析依赖 blocker、激活 return point、签发新 claim 并刷新 checkpoint。无需等待另一个控制面 Session。 / When the current Work is a dependency leaf with a declared return point, call `continuity_work_transition` as soon as evidence is ready; it completes the dependency, releases the old claim, resolves the dependency blocker, activates the return point, issues the new claim, and refreshes the checkpoint in one State Event. Do not wait for another control-plane session.
- 最后一个 active Work 完成后，`continuity_resume` 必须接受零 active/claim 的 idle State，并返回 `next_action=activate-next-work`。该 idle binding 只允许 `continuity_work_activate`；activation 在一个 Event 中创建或激活 Work、签发 claim，并发布验证后的 checkpoint。 / After the last active Work completes, `continuity_resume` accepts an idle State with no active Work or claim and returns `next_action=activate-next-work`. That idle binding allows only `continuity_work_activate`; activation creates or activates the Work, issues its claim, and publishes a verified checkpoint in one Event.
- `continuity_work_complete`、claim recovery、activation 和 dependency transition 都在返回前刷新并验证 checkpoint。 / `continuity_work_complete`, claim recovery, activation, and dependency transition all refresh and verify the checkpoint before returning.
- Recovery Envelope 的 `completion_authority: false` 表示 envelope 本身不能写 State，不是永久否决。窄化的本地 completion authority 由 `continuity_work_transition` 在调用时根据 active claim owner、scope、source、lease、workspace、evidence、checkpoint 和 return point 自动裁决。 / `completion_authority: false` on a Recovery Envelope means the envelope itself cannot write State; it is not a permanent veto. `continuity_work_transition` grants the narrow local completion authority at call time after checking the active claim owner, scope, source, lease, workspace, evidence, checkpoint, and return point.
- transition 失败时只处理返回的 `failed_gate`，不得手工编辑 SQLite、拆分 complete/activate 或等待人工猜测下一步。 / On transition failure, address only the returned `failed_gate`; never edit SQLite, split completion from activation, or wait for a human to infer the next step.
- 只能通过 source-bound activation tool 激活 successor；中断后可留下 ready Work 供重试。 / Activate a successor only through the source-bound activation tool; a ready Work may remain after an interrupted claim.
- 已有项目的 MASTER 和 STATUS 保留其治理角色。 / Existing project MASTER and STATUS retain their declared governance roles.
- candidate memory 和 prose 不能覆盖 current State、source evidence 或 claim scope。 / Candidate memory and prose never override current State, source evidence, or claim scope.
- 在 lease 到期前主动 heartbeat；canonical source 在 active Work 内合法演进时，stale heartbeat 会自动重新哈希当前 source、绑定 active Work evidence 并刷新 checkpoint，不回滚或覆盖其他 Session 的 notes。已过期时用新的 claim identity reclaim。任一步失败均保持只读并返回具体门条件，不在业务项目中开发控制面。 / Heartbeat before lease expiry. When canonical sources legitimately evolve during active Work, a stale heartbeat re-hashes current sources, binds evidence to the active Work, and refreshes the checkpoint without reverting or overwriting other-session notes. Reclaim an expired lease with a new claim identity. Any failure stays read-only with a precise gate; do not develop the control plane in the product project.

## Answer Discipline / 回答纪律

- `[continuity.answer.direct]` 第一行直接回答用户问题，不复述问题。 / Answer the user's question directly in the first line; do not restate it.
- `[continuity.question.no-advance]` 问题只授权回答；只有明确的 `开始执行`、`继续` 或等效命令才推进 active Work。 / A question authorizes an answer only; advance active Work only on an explicit execution command.
- `[continuity.answer.no-recovery-narration]` 普通问答不输出进度台账、目标态全表、Skill 列表或恢复旁白。 / Do not emit progress ledgers, target-state tables, Skill lists, or recovery narration for ordinary questions.
- `[continuity.answer.bounded]` 默认只给结论和最多五条必要证据；表格仅用于用户明确要求的报告或真正需要对比的内容。 / Default to one conclusion plus at most five necessary evidence points; use tables only for explicitly requested reports or material comparisons.
